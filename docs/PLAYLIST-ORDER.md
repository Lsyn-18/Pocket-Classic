# 歌单列表与歌单内歌曲顺序 · 0.10.4

本轮同时修复「我的歌单」列表和歌单内歌曲的读取顺序。歌单列表使用移动端创建、收藏列表及置顶信息；歌单内歌曲按云端保存的 ID 序列显示，播放队列沿用页面顺序。

## 我的歌单列表

原来仅调用旧的 `/api/user/playlist` 合并接口，且只取前 100 项，未使用移动端创建、收藏列表的置顶与排列信息。现在改读 `/api/user/playlist/create` 和 `/api/user/playlist/collect`，使用 `includeTop`、`includeRedHeart` 与 `isWebview` 参数。

按每页 100 项读完两个分组，保留各自返回顺序，再按创建列表、收藏列表依次合并。重复出现的置顶歌单只保留首次位置；本账号「喜欢的音乐」继续独立显示。不会按名称、编号或更新时间重新排列。读取失败显示可重试错误；每组最多支持 5,000 项。

安卓为这两个接口增加 EAPI 请求编码，独立的 Node 密码学固定向量验证路径签名与加密结果。编码按网易云的固定协议实现；本地登录凭证仍通过 Android Keystore 保存。普通登录、歌曲详情及播放地址继续使用原有请求路径。

接口依据：[创建列表](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/user_playlist_create.js)、[收藏列表](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/user_playlist_collect.js)。响应的 `data.playlist` 路径另参考 [有类型的接口定义](https://github.com/nonhana/hana-music-api/blob/master/src/modules/user_playlist_create.ts)。

## 歌单内歌曲

原来的安卓与浏览器读取路径直接显示 `playlist.tracks`。这个数组提供歌曲详情，可能只包含部分歌曲，也不能替代歌单保存的完整 `trackIds` 顺序。固定输入已复现乱序和缺项：

| 输入 / 输出 | 歌曲 ID |
| --- | --- |
| 歌单保存顺序 | 31、17、9 |
| 歌曲详情返回顺序 | 17、9、31 |
| 修复后显示与入队顺序 | 31、17、9 |

普通歌单先载入最多 1,000 首，更长歌单通过「加载更多歌曲」继续读取。每次重新进入歌单都会读取保存顺序，并按 ID 建立详情索引。当前页面缺失的详情按每组最多 500 首补齐，再按保存顺序输出；详情响应即使乱序，也不改变歌曲位置。完全无法获取详情的歌曲会跳过，其余歌曲的相对顺序保留，分页位置仍按 ID 序列推进。

继续加载时沿用同一份顺序，避免加载途中歌单变动导致页面拼接乱序。返回歌单列表再重新进入可刷新最新保存顺序。网络失败可重试，账号切换后的旧响应会被丢弃。

安卓使用独立的 `PlaylistTrackIndex`，浏览器服务在歌曲库中执行同一规则；网页端把已加载的顺序原样传给播放队列。现有列表与队列上限为 5,000 首，队列包含当前已加载的歌曲。

## 范围

- 「我的歌单」跟随移动端接口返回的创建、收藏与置顶排列，歌单内歌曲跟随云端保存顺序。网易云 App 仅存于本机的分组显示偏好不能据此推断。
- 以云端保存顺序为准。网易云 App 仅在本机临时切换的歌名、歌手、时间升降序等显示方式，不等于云端保存顺序，也不会自动同步到本项目。
- 随机播放设置独立于列表排序；开启随机播放时，播放下一首仍按用户的随机播放设置执行。

## 验证

138 项 Node 检查与 42 项安卓单元测试通过，安装包、测试包与 Lint 构建通过，Lint 为 0 错误、26 项已有警告。固定 EAPI 协议的 ECB 编码使用定向 Lint 标注说明用途。

- 回归测试先在原始服务读取函数上复现详情乱序、缺项，再验证修复后的同一入口。
- 另在同一服务入口复现旧合并列表与移动端分组顺序不同；验证置顶去重、自定义排列、超过 100 项时的续页、空分组、异常响应和账号切换。
- 使用文档中的公开示例用户、无登录凭证，对创建和收藏两个 EAPI 地址分别完成只读请求，均返回 HTTP 200、业务码 200 与 `data.playlist` 数组，核对移动端编码与响应格式。
- 验证空 ID 序列、缺失 ID 字段的兼容回退、重复 / 无效 ID、详情不可用、失败重试、账号切换与无效分页。
- 2,003 首合成歌单在实际打包页面中完成 1,000 / 1,000 / 3 首三页读取，歌曲详情故意乱序并缺项，最终显示与传入安卓桥接的队列仍为完整保存顺序。
- 实际打包页面及浏览器 / 安卓队列路径同时检查移动端歌单顺序与歌曲顺序；旧浏览器网关验证分页参数不会被丢弃。

这些验证使用合成数据和模拟原生桥接。当前没有安卓设备，未使用真实网易云账号逐项对照手机 App 的实际排序。
