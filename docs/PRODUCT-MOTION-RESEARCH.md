# Pocket Classic 产品展示运镜调研与新版预览

日期：2026-11-08。

历史探索记录：本页的环绕运镜已放弃，Android 0.8.1 当前采用并已真机验证的方案为 [转轮序章](WHEEL-OPENING.md)。

结论：采用「同侧推近 → 单条上升环绕 → LCD 亮屏停留 → 平稳退远」的一镜到底。保留大幅度运镜和直立机身，将总时长从 5 秒调整为 6.2 秒，LCD 完全点亮后仍停留 0.8 秒。

本轮交付为新的交互预览和调研记录，尚未改变安卓应用的启动行为。

## 上一版为什么仍可能显得不够顺

这部分来自当前预览源码与投影计算，不是对真实设备掉帧的诊断。

1. **来回反向太多。** 相机先从右侧约 65° 进入，再反向去左侧约 62°，随后又去右上方约 55°；在短时间内连续改变主运动方向，容易呈现摇摆感。
2. **数学连续不等于感知均匀。** 独立插值角度、距离和焦点，即使连接处没有跳变，画面中的机身尺寸和位置仍可能突然加速。
3. **多个参数反复减速、起步。** 构图重点附近的局部缓动叠在一起，形成分段动作的感觉。
4. **镜头角度与额外歪斜曾混在一起。** 用户已要求机身直立，因此不应再通过旋转机身或画面滚转制造动感。
5. **轨迹节奏与运行性能是两件事。** 本轮能验证路径和投影变化，尚未测得新预览在安卓设备上的逐帧耗时。

## 新版「流光巡游」

### 路径

- 整机从**左侧约 65°**开始，保持直立；推近时与转轮处于同一侧，减少开头的一次大幅反向。
- 在**左侧约 62°**掠过转轮，继续运动，避免每到一个部件都完全停下。
- 沿一条上升弧线越过机身前方，进入 **LCD 右侧约 55°、上方约 48°**的细节构图。
- LCD 完全点亮后稳定停留 **0.8 秒**；灯光继续轻微流动，画面保持有生命感。
- 从右上方平缓退远、转正，结束于可以衔接真实播放器的位置。

### 默认时间分配

| 时间 | 行为 |
| --- | --- |
| 0.00–约 0.65 秒 | 从静止开始柔和加速，展示直立整机 |
| 约 0.65–1.50 秒 | 同侧推近，进入转轮构图 |
| 约 1.50–3.80 秒 | 连续抬升与环绕，在接近 LCD 时逐渐减速 |
| 3.80–4.60 秒 | LCD 已完全亮起，稳定停留 0.8 秒 |
| 4.60–6.20 秒 | 平稳起步、退远、转正，缓慢收束 |

转轮实际经过时刻随窗口比例略有变化，因为时间映射考虑画面中主体的投影速度。默认桌面预览约为 1.50 秒，窄屏约为 1.46 秒；LCD 停留和总时长保持一致。

### 运动与镜头

- **先设计空间路径，再分配时间。** 角度、对数距离和焦点共用一条连续轨道；转轮附近仍有相机位移，只有 LCD 安排明确停留。
- **按投影运动重新分配行进速度。** 参考机身、转轮、LCD 及边缘的投影变化，降低近距离移动时的突然放大感。该方法属于本项目设计，未声称来自任一品牌的内部实现。
- **缓起、稳定行进、缓停。** 用连续的速度坡道组织整段行程，进入 LCD 停留前逐渐减速，退出停留后重新平滑起步。
- **固定视场角 24°。** 配合更远的相机距离保持构图尺度，减轻近距离透视夸张；全程不通过改变视场角制造突然变焦。此数值是本项目参数，不代表参考片使用的镜头。
- **稳定竖直方向。** 机身不做动画倾斜，镜头无额外滚转；保留运镜带来的自然俯仰和透视变化。
- **控制预览负担。** 继续使用一个 WebGL 渲染器和一个场景，不增加全屏模糊或重型运动模糊；预览像素比上限由 1.6 调整为 1.4。是否达到目标帧率需运行测量。

## 验证结果与限度

已完成：

- 打包、脚本语法与 HTML 片段格式检查。
- 736px 和 320px 两种宽度下，检查整机、转轮和 LCD 重点构图的主体边界。
- 完整时间轴检查镜头不进入机身、不落到地面下方，且无额外滚转。
- 5.8 / 6.2 / 8 秒三种总时长下，确认 LCD 完全点亮后始终稳定停留 0.8 秒。
- 在统一的投影探针与每秒 240 次采样下，对上一版 5 秒方案和新版 6.2 秒方案进行计算比较。

| 计算指标 | 上一版 | 新版 | 变化 |
| --- | --- | --- | --- |
| 投影速度峰值 | 1.731 | 0.743 | 约下降 57% |
| 投影加速度 95 分位 | 6.180 | 2.303 | 约下降 63% |
| 投影加速度变化率 95 分位 | 58.439 | 33.910 | 约下降 42% |

指标来自同一组经过平滑限制的标准化投影坐标；单位分别为每秒、每平方秒和每立方秒。比较包含路径重排、时长增加和镜头参数调整的共同作用，不能据此把收益归给某一个改动。这些是轨迹计算值，**不是帧率、掉帧率或用户感知评分**。

尚未完成：新版浏览器像素级画面核验和安卓真机帧率测量。此前本地文件浏览预览被浏览器策略拒绝，本轮未尝试绕过该限制。正式接入前仍需检查真实画面与设备性能；若存在渲染掉帧，要独立处理渲染负担，而不能仅靠延长动画。
