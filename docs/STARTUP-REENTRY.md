# 0.9.1：画报与转轮开场不显示

> 以下为 0.9.1 的历史实现。用户明确要求只在后台进程被清理后的冷启动显示，因此每次桌面触发已在 0.9.2 撤回。当前规则见 [冷启动开场与播放页调整](STARTUP-PROCESS.md)；静态画报被提前移除的修复继续保留。

## 定位结果

0.9.0 存在两条可导致开场缺失的路径。

1. **桌面再次打开复用了已结束的页面。** `PlayerViewModel.claimOpening()` 只在整个 ViewModel 生命周期内返回一次 `true`；`MainActivity` 未处理桌面再次打开时的新 Intent。安卓保留任务后，点击桌面图标可能只是把原播放器带回前台，前端开场已结束，没有再次创建画报或开始转轮时间轴。上一轮测试主要使用关闭活动后重新创建的路径，没有覆盖这一保留任务的入口。
2. **减少动态效果提前清掉了静态画报。** `startup-view.mjs` 在首个模型帧直接结束开场，随后的清理回调连画报一起移除，绕过了画报准备完成后的 200ms 淡出。新增回归先在旧逻辑上复现了“首个模型帧后，开场已结束而画报尚未完成”的失败，再验证修复。

用户反馈时没有安卓设备，无法读取其手机上具体的开场结束原因或动态效果偏好；上述是代码中确认并修复的两条路径，不将某一条猜测标为已在用户手机复现。

## 修改后的入口规则

| 入口 | 行为 |
| --- | --- |
| 新建播放器页面 | 加载画报完成后播放完整五秒转轮序章。 |
| 再次点击桌面图标 | `singleTop` 将标准 `MAIN + LAUNCHER` Intent 送到现有活动，重新允许本次开场并重载播放器页面。即使上一轮跳过，也可以重新显示。 |
| 最近任务、通知返回或重新获得焦点 | 继续原播放器，不因普通恢复而重复插入五秒开场。通知入口没有 `MAIN + LAUNCHER`，不会重新触发。 |
| 同一次进入中的页面重建 | 保留已领取的开场标记，避免重复播放。 |
| 系统或应用开启减少动态效果 | 保留静态画报，等实际模型就绪后交叉淡出；继续遵循偏好跳过转轮运镜。 |

`OpeningSession` 独立保存一次进入的开场标记，并区分桌面 Intent 和普通返回。页面重载不调用播放暂停、音量修改或队列重建命令；音乐仍由原生 Media3 管理。重载前的未完成请求按页面代次过滤，避免旧页面的异步结果回送给新页面。

画报版本更新为 0.9.1；升级后按首次画报时长显示，日常使用较短画报。版本记忆和开场触发是两件事：记住画报版本只缩短时长，不永久禁用开场。

## 验证与限制

- 115 项 Node 检查通过，包括减少动态效果时画报必须等候准备完成的回归。
- 28 项安卓单元测试通过，包括冷入口、重复桌面入口、同次重建、通知 / 外部链接返回的开场标记策略。
- 实际安卓内置 HTML 在浏览器中，配合模拟原生桥接，完成冷启动、重新允许后的页面重载、普通恢复、已保存减少动态效果、系统减少动态效果五种检查；画报与转轮顺序正确，无脚本、着色器或 WebGL 错误。模拟桥接不能替代真实安卓桌面 Intent 的验证。
- 安卓安装包、测试包构建及 Lint 通过，0 错误、26 项既有警告。桌面重复进入的设备测试已补充并编译。
- **本轮没有安卓设备，未进行覆盖安装、真实桌面点击、通知返回或后台播放的真机回归。** 0.9.0 的既有真机记录不作为这次修复的真机结论。

## 有设备后的复验

1. 同签名覆盖安装 0.9.1，关闭“更多 → 显示与动态效果 → 减少动态效果”，首次打开应出现画报和完整转轮序章。
2. 完成或跳过开场后按 HOME，再点桌面图标；连续重复两次，确认每次均重新触发。
3. 播放时按 HOME，再点桌面图标，检查音乐、进度和系统媒体音量保持；从最近任务和通知返回时应直接继续播放器。
4. 开启应用或系统减少动态效果后重新打开，确认静态画报保留，转轮运镜跳过；还原测试前的偏好。
