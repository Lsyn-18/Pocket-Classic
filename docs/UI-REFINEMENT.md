# 0.6.0 界面改进

保留 Classic 的机身比例、蓝色菜单选中条和转轮操作，围绕阅读、反馈和状态一致性完善界面。

## 2026-11-07 后续修正

LCD 原来虽以 1280 × 960 绘制，仍要经过三维纹理缩小、三线性 mipmap、玻璃混色和最高 2 倍的最终场景画布。Chrome 的 390 × 844 / DPR 3 检查复现了最后一层只有 DPR 2 的输出；继续提高纹理尺寸或局部锐化不能移除这层放大。现在将同一高清画布直接交给浏览器合成，用三个投影角点生成仿射矩阵，随三维屏幕同步倾斜。纹理仍用于三维倒影及基线比较，机身维持原场景性能预算。

播放页去掉进度背景框、说明标题与圆点，仅保留 3 个逻辑像素高的细线、时间和独立音量。电池配色改为鲜绿和低电量红色；环境增加可见的缓慢呼吸光，播放时加快，减少动态效果时静止。

长按 480 毫秒后，以每秒 10 秒持续定位，持续 1.8 秒后加速至每秒 24 秒；松手或取消手势停止，不追加切歌。原生桥串行合并请求，只保留最新目标，避免 250 毫秒回传的旧进度覆盖正在定位的位置；更换歌曲时清除隔离状态。

原帮助只有底部按钮可聚焦，横屏 `showModal()` 会自动滚到底部。现在打开时聚焦标题、滚动到顶，提供固定在顶部的关闭入口。底部「阅读」按钮已移除，播放页歌曲信息仍可打开完整详情。

原三维容器用 `inset` 给工具栏让位，使场景背景止于工具栏上方；安卓还在 WebView 外套了 `safeDrawingPadding()`。现在场景与环境铺满窗口，只给相机取景预留控制空间；安卓根容器填满窗口并允许延伸至挖孔区域。

验证：82 项 Node 检查及 16 项安卓单元测试通过，安卓 APK / Lint 构建通过（Lint 无错误，有现有警告）。Chrome DPR 3 下检查 390 × 844、844 × 390、明暗主题、指针与键盘长按、触摸取消、松手后不再定位、帮助初始滚动位置、减少动态效果与页面错误。当前无连接设备，安卓挖孔、安全区域、合成清晰度与长时间性能仍需真机验收。

## 已实现

- LCD 主菜单采用 14 逻辑像素，增强辅助文字对比；可切换大字菜单。长标题在选中停留后滚动，减少动态效果时保持静止。
- 子菜单、当前播放歌曲、音质勾选、开关使用不同标识；长列表增加位置计数和滚动指示。
- 播放页显示缓冲、暂停、试听和实际返回的音质；进度模式高亮，音量与进度分层呈现。
- 长按中央键或点击播放页右下角进入真实播放队列；歌曲信息区域可打开阅读视图。
- 播放页歌曲信息打开支持键盘与语义标签的详情界面，显示完整歌名和专辑信息。
- 错误在 LCD 主体显示原因与重试/返回操作；登录过期显示重新连接；空列表说明下一步。
- 连接入口在未登录时突出，登录后收紧；体感、重新校准、机身颜色和帮助收进更多选项。
- 银色按键符号加深，黑色机身向中性石墨色调整，倒影缩短减淡。按后续反馈移除中央键下压和转轮点按变色。
- 机身颜色和明亮/深色/跟随系统环境分离；网页与安卓保存偏好，大字和减少动态效果独立可设。
- 安卓登录弹窗突出主操作，明确同机扫码步骤和授权阶段，并协调明暗配色。

## 验证方式

Node 回归覆盖队列导航、失败重试、请求音质与实际音质区分、主题独立设置、LCD 命中与大字行高、菜单状态标识及原有播放/传感器逻辑。

构建：`node web-model/build.mjs --publish --android`。受限 Windows 环境可增加 `--isolated`，由 Node 解析依赖并将源文件提供给打包器，避免打包器向上查找目录。

具体浏览器尺寸、安卓构建与测试结果见 DEVICE-TESTS.md。真实账号音质、TalkBack、户外可读性与真机主观触感仍需在对应环境验收；自动化与浏览器检查不替代这些结果。
