# 手机媒体音量同步

更新：2026-11-08，Android 0.8.2。

## 修复后的行为

| 操作 | 结果 |
| --- | --- |
| 按手机音量键 | 调整系统媒体音量，播放器的百分比和音量条同步变化；暂停时也控制媒体声道 |
| 在音量模式转动转轮 | 直接调整同一系统媒体声道，按实际接受的档位更新显示 |
| 手机静音后转动转轮 | 从最低有效档位恢复，低档位手机也不会因取整而始终停在静音 |
| 切换歌曲或播放队列 | 保留手机现有媒体音量 |
| 在后台调整音量后返回 | 立即读取最新系统媒体音量 |

## 原因与实现

0.8.1 将前端音量写入 `MediaController.volume`，状态也读取播放器自身增益，默认回退值为 65%。这与手机媒体声道是两套数值；真机复现了系统媒体音量为 0、应用仍显示 100%。仅指定活动的默认音量声道后，按键测试仍未改变媒体音量。

0.8.2 的 `NativeMediaVolume` 通过 `AudioManager` 读取和设置 `STREAM_MUSIC`，将手机的实际档位换算为 0–1。`MediaVolumeScale` 覆盖不同范围、非零最小值、静音及边界；安卓 8 使用最小值 0，安卓 9 起读取系统提供的最小值。新增普通的 `MODIFY_AUDIO_SETTINGS` 权限，不申请特殊设置访问权限。

原生 WebView 在网页处理前接收音量键并调节媒体声道，消费按下和松开事件以防重复调整；保留 Android 系统音量面板。界面载入时为容器请求键盘焦点，活动默认声道也设为媒体。

Media3 保持增益 1，不再叠加应用独立音量。队列请求不携带音量，队列启动也不恢复旧值。前台状态每 250 毫秒读取真实音量，按键及返回前台时立即刷新；音量更新先于队列状态屏障处理。设置音量的回执返回系统实际音量与单档步长，前端合并快速请求，尚有新目标时忽略旧回执和旧状态，完成后按系统档位修正显示。

浏览器预览继续使用 HTML 音频本身的音量；系统媒体音量同步仅用于安卓原生客户端。

## 验证

- 106 项 Node 检查：系统音量变化事件、加载队列时同步、快速请求合并、旧状态防回退、真实档位回执、失败后恢复读取，以及转轮在粗档位手机和浏览器的步长。
- 24 项安卓单元测试，包括 0–7、0–15、0–25、0–100、0–150 和非零最小值的范围换算、越界及无效值、固定范围。
- 小米 2210132C / Android 16 真机，媒体音量范围 0–150：初始 50 对应 33.33%；应用设置与转轮改变真实系统音量；音量减键将 50 调至 40，界面读取 26.67%；静音显示 0、转轮恢复、HOME 后修改音量并返回均通过。
- 真机专项使用 Android 原生按键事件和真实系统音量读数，未播放测试音频、清空账号或修改音乐库。正常完成后恢复该轮启动时读取的媒体音量。
- APK 构建与 Lint 通过，0 错误、25 项现有警告。记录见 [真机检查](DEVICE-TESTS.md)。
